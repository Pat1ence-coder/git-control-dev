# Generative Git

用于 VS Code / Cursor 的 Git 工作台，将提交历史、未暂存更改、合并冲突和提交审查集中在编辑器页面中。

## 功能

- **提交历史**：以分支图和提交列表展示历史，查看提交信息及文件差异。
- **未暂存更改**：显示修改、删除和未跟踪文件，支持查看差异和逐文件暂存。
- **分支合并**：选择本地分支发起合并，查看冲突并中止进行中的合并。
- **冲突处理**：支持保留当前、保留传入、两者都保留和本地规则草拟；应用前查看完整差异。也可使用官方合并编辑器和复杂冲突处理流程。
- **审查与提交**：查看实际暂存内容、编辑提交说明，并通过编辑器官方 Git 流程确认提交。
- **本地备份**：保存冲突修改前的完整原文，支持打开和手动清理备份。
- **演示模式**：使用模拟数据体验合并、解决冲突和提交流程，不读写真实仓库内容。

## 安装与打开

需要 VS Code / Cursor 1.85 或更高版本、可用的 Git，以及已启用的内置 Git 扩展。实时功能需要可信的本地工作区。

在扩展面板选择 **从 VSIX 安装**，安装构建生成的扩展包并按提示重新加载编辑器。打开 Git 仓库后，点击活动栏图标，或运行 **Generative Git: 打开工作台**。

可从源码构建安装包，需要 Node.js 18+、npm 和 Python 3：

```bash
npm ci
npm run compile
python3 scripts/package-vsix.py
```

## 使用方式

### 查看与暂存

切换到 **实时** 模式，在“未暂存更改”列表中点击文件查看差异。新文件会直接打开内容。点击文件旁的 **暂存**，将该文件的完整工作区版本放入暂存区。未保存的编辑需要先在编辑器中保存或撤销。

多仓库工作区可使用仓库选择器切换。Git 状态变化会更新列表，也可点击刷新。

### 解决冲突

选择本地分支并确认合并。出现冲突时，点击冲突数量查看摘要，再展开冲突详情。

普通文本冲突可以选择解决策略，检查完整差异后点击 **应用并暂存**。也可打开官方合并编辑器手动处理。删除、重命名、二进制等复杂冲突可使用 **官方暂存冲突（全部）**；该操作处理当前仓库的全部冲突，官方流程会提示保留或删除，中途取消可能保留已完成的部分暂存。

“AI 草拟”使用本地规则，不调用外部模型，结果需要人工审查。

### 审查与提交

点击 **审查并提交**，逐文件查看暂存差异，填写提交说明后点击 **确认提交**。

提交遵循编辑器的分支保护、诊断检查、签名、Sign-off 和保存提示设置。默认提交已暂存版本；若在官方提示中选择“保存并提交”，相关文件会按该选择更新暂存内容。需要审查最新内容时，可取消提交，保存并暂存后重新加载审查。

仓库或暂存内容变化时需要重新审查。提交不会执行后续推送或同步。提交说明草稿保留在当前工作台会话中。

## 命令

| 命令 | 功能 |
| --- | --- |
| Generative Git: 打开工作台 | 在编辑器标签页打开工作台 |
| Generative Git: 刷新仓库 | 更新实时仓库状态 |
| Generative Git: 运行演示场景 | 进入模拟合并流程 |
| Generative Git: 打开冲突修改备份 | 查看保存的冲突原文 |
| Generative Git: 清理冲突修改备份 | 确认后删除本扩展保存的备份记录 |

## 数据与隐私

- 本插件没有直接外部网络请求，不调用外部模型，也不自动上传代码。官方 Git 操作遵循宿主及仓库设置，可能运行已配置的 hooks。
- 冲突备份保存在本机扩展存储目录，包含文件绝对路径和完整原文，可能包含敏感信息。备份为明文，不自动过期，可通过清理命令删除。
- 复制冲突只在用户点击后写入剪贴板，不自动发送到聊天。
- 本插件对外部错误只显示受控摘要。编辑器内置 Git 的原生弹窗和日志由宿主管理。
- 提交前校验不能锁住其他终端、扩展或 hooks；应避免同时修改同一仓库。

## 功能范围

提交图最多展示 36 条提交，读取最多 24 个本地分支引用。合并提交显示相对第一父提交的差异；根提交的文件差异需通过编辑器内置历史查看。

本地文本冲突处理限制为 180 KB，差异显示最多 180,000 个字符。超大文件、二进制及特殊文件类型应使用官方处理流程。无法验证关联的 Git 元数据布局会停止操作。

远程同步、PR 管理，以及 rebase、cherry-pick、revert 等完整流程，请使用编辑器内置源代码管理或其他相应工具。
